# 评测第一仗：考题集、baseline 与返回形态

评测的判断与尺子在洞察仓[搜索好不好用怎么判断](../../../data/insight/default/search-evaluation.md)，近景安排在路线图[当前优先](../../../data/roadmap/intro/index.md)。本篇只管这一仗怎么打：考题集、指标、对照与队列。

适用边界：只评专用搜索行为这一层——shell 行为不经过搜索工具，AI 直接从命令输出拿答案。真值的存在性已由[配对率实测](2026-10-11-pairing-rate.md)验证：专用搜索配对率 51.0%，约 1600 题的规模足以建考题集；查询分布的事实源在 [hermes-session-analyzer 研究记录](2026-10-11-hermes-session-analyzer.md)。

## 考题集

- **正向题**（约 1600 题）：抽取配对子集的打开文件路径——搜索后打开的那份文档就是期望结果，测「能不能一步到位」。
- **负向题**：收连环搜的起点查询，不需要真值，行为即判据——测「会不会把 AI 逼去绕弯」。
- **概念题**：真值不在文件里的概念查询靠标注，与查询改写双组同批出题，同时回答「词面够不够」。
- **校验前置**：抽样人工校验「打开的就是想要的」，顺序在构造之前——AI 可能凑合打开第一个看着相关的文件，把次优解当标准答案会高估现有工具。

会话级关联的引用只当后验，不出题。

## 指标

在跑 baseline 之前定死：top-k 名内有没有一个能让 AI 直接往下走的结果（到手还要几轮），不问「排第几」。理由与口径见洞察「指标」节。

## 对照

- **baseline**：原型当前形态（路径 + 分数）跑同批题。
- **双组**：同批加 LLM 查询改写（把「检索」展开成「检索 OR 搜索 OR 查找」），回答词面够不够；同义词短板目前是猜想，让数字说话。
- **形态**：返回形态最小版本 = 路径 + 片段 + 范围 + 条数。回放测不了「有片段是否省一轮」，薄层人工判「够不够下一步动作」，几十题定方向。
- **重尺**（agent 模拟全流程）只做裁决，不作起点。

## 队列

1. 抽取配对子集的打开文件路径，构造正向题
2. 收连环搜的起点查询当负向题
3. 抽样人工校验「打开的 = 想要的」偏差
4. 定死 top-k 指标，跑 baseline
5. 同批加 LLM 查询改写，双组对照
6. 看对照数字决定下一步：调分词与同义词、上向量搜索，还是就这样够用
