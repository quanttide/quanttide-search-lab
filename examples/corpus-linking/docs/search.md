# 阶段 3 建索引与查询报告

## 结论

查询入口已可用：`/usr/bin/python3 scripts/search.py "某主题"` 返回余弦相似度 top-k 的片段、出处与正文摘录。两项一致性校验全过——**校验 A（自洽）50 / 50，校验 B（对阶段 1 的跨领域重复对）72 / 72**。

但要说清两件事：

1. **校验 B 是同源的**：这 72 对本身就是用同一批向量算出来的，它只能证明「检索链路通」，不能证明「召回好」。
2. **TODO 3.2 本轮没做**：拿真实主题实测、判召回对不对——判「对不对」是意义判断，须人来判，是用户的活（见文末「本轮留白」）。

本轮**不建 ANN 索引**：22811 条向量全量点积实测 13.6 ms/次，「建索引」在当前规模下就是「加载向量 + 精确检索」，引 faiss / hnswlib 省不出时间、只多依赖，规模上去再议。

## 用法

```bash
/usr/bin/python3 scripts/search.py "某主题"          # 默认 top-10
/usr/bin/python3 scripts/search.py "某主题" --k 3    # 只要前 3 条
```

每行四个字段，制表符分隔：`score`（余弦）、`id`、`source`（`领域仓#相对路径`）、正文前 120 字（空白压成单行）。门禁结果与耗时走 stderr，stdout 只有结果行，方便管道接。

出错不糊弄：

| 情况 | 行为 | 退出码 |
| --- | --- | --- |
| 查询为空 / 缺查询 | 打印明确原因与用法 | 2 |
| ollama 或 bge-m3 不可用 | 打印连不上的地址与排查提示 | 1 |
| 指纹不符（语料被改过） | 门禁拒绝运行，提示重跑阶段 0 | 1 |

## 这份结果怎么读

- **余弦相似度**：两个向量方向有多接近，1 表示同向、0 表示无关。查询串与每条片段各算一个值，按值降序取前 k。
- **L2 归一化**：把每条向量长度缩到 1，之后点积就等于余弦，省一次开方。片段向量与查询向量都归一化。
- **top-k**：只看分数最高的 k 条（默认 10），其余 22801 条不看。
- **为什么不上 ANN**：ANN（近似最近邻，faiss / hnswlib 这类）是向量百万级、内存装不下时才值得的取舍。这里全量点积实测 13.6 ms/次（14.3 ms、14.5 ms、14.1 ms 三次带载实测也都在 15 ms 内），精确检索又快又是真值，所以「建索引」= 加载向量 + 点积。真正的耗时不在检索：编码查询一次 3.7 至 7.6 秒（bge-m3 推理），点积只占其中约 0.4%。
- **门禁**：每次运行先跑 `manifest.py --check` 核对语料与脚本指纹，指纹不符拒绝运行——语料是活的，别的会话改一次 `domains/`，向量就与片段失配。

## 两项校验怎么做

**校验 A（自洽）**：固定种子 42，从 22811 条里不放回抽 50 条，把每条**自己的正文**当查询重新过一遍 bge-m3 编码，与全量向量算余弦，看第一名是不是它本人。期望 50 / 50，实际 **50 / 50**。

这条过的是全链路：编码 → 归一化 → 全量点积 → 排序。任何一环错位（行号与 id 对不上、归一化漏了、查询向量维度错），top-1 立刻对不回本人。

**校验 B（对阶段 1）**：取 `data/duplicates.tsv` 里 `source` 两侧领域仓不同的对（586 对里跨领域的 **72** 对，分母 72），用 A 侧（`id_a`）的正文当查询，看 B（`id_b`）的分数是否不低于第 10 名门槛（并列算命中）。实际 **72 / 72**，0 对 id 缺失。

**必须写明的一条**：这 72 对本身是用同一批向量算出来的，属**同源**——它只能证明「检索链路通」，不能证明「召回好」。拿同一套向量既造题目又判卷，命中是必然的；真正的召回检验要靠人拿真实主题去判（TODO 3.2）。
